# RTL Coding

Distilled from rtl-skills (`vdesign`, `vfill`, `CodingStyle`, `DesignPatterns`;
Apache-2.0) and lessons from VeriFlow-CC runs. Only rules that prevent real bugs
or keep agents consistent are kept. Patterns and the bug catalog are in
`patterns.md` next to this file.

## 1. Plan before you write (put it in your report)

The spec's port list is the contract: copy names, widths and directions
verbatim. Before coding, decide and record as `assumption` claims anything the
spec leaves open. Then write down, briefly:

| Decide | Record |
|--------|--------|
| Output timing | each output `reg` (from a flip-flop) or `comb` (same-cycle function of inputs/state) |
| Latency / throughput | cycles from input accepted to result visible; results per cycle |
| Control | FSM states, reset state, every transition, `default` recovery |
| Pipeline | one row per stage: registers owned, work done, valid qualifier, stall behavior |
| Storage | every register/RAM: width, reset value or "not reset, qualified by valid" |
| Inputs | each input: level, pulse (min width) or data (valid with which qualifier) — a missed pulse is a bug |
| Clocks | every clock domain; for each crossing, the P17 mechanism and its latency bound |
| Boundaries | each compare against a limit (`==`, `>=`, wrap point) and which pointer — current or next — feeds each flag |
| Patterns | which entries of `patterns.md` apply (scan the reflex triggers) |

If the design needs a port or parameter the spec does not have, stop and record
an `assumption`; do not add it silently.

## 2. Hard rules (checked by `python3 tools/mae.py run style`)

The `style` tool must PASS for `rtl_freeze`. Rule IDs as the tool reports them:

| ID | Rule |
|----|------|
| R01 | `` `default_nettype none `` first, `` `default_nettype wire `` after `endmodule` |
| R02 | Verilog-2005 only: no `logic`, `always_ff/comb`, `typedef`, `enum`, `struct`, `interface`, `assert`, `.*`, `'0` |
| R03 | no `casex` |
| R04 | no `#delay` |
| R05 | no declaration initializers (`reg x = 0;`): reset is the only initialization |
| R07 | every register written in a clocked block ends in `_ff` (memory arrays exempt) |
| R08 | nothing else ends in `_ff` (wires, ports, comb regs) |
| R09 | synchronous reset only: the sensitivity list holds the clock edge and nothing else |
| R11 | named port connections only |
| R12 | instance names start with `u_` |
| R13 | no variable `/` or `%` (constant power of two → shift/slice; else redesign) |
| R14 | no `output reg`: `output wire` driven by `assign port = x_ff;` |
| R15 | `<=` only in clocked blocks, `=` only in `always @*` |
| R16 | synchronizer flops `*_meta_ff` / `*_sync_ff` are declared `(* ASYNC_REG = "TRUE" *)` |

Waive one rule on one line only with a reason a reviewer accepts:
`// mae-style: allow R07 <reason>`.

`lint` (Verilator `-Wall`) must also be clean. Waive a Verilator warning narrowly
(`/* verilator lint_off X */ … /* verilator lint_on X */`) with a comment; never
waive `WIDTH*` on arithmetic or concatenation without saying why it is safe.

## 3. Shape of a module

```verilog
`default_nettype none
// reg_slice.v : one-stage valid/ready register slice.  Generated by AI agent
module reg_slice #(
    parameter DATA_W = 8              //! data width
) (
    input  wire              clk,     //! clock
    input  wire              rst_n,   //! synchronous reset, active-low (per spec)
    input  wire              s_valid, //! upstream valid
    output wire              s_ready, //! comb: slot free or being drained
    input  wire [DATA_W-1:0] s_data,  //! upstream data
    output wire              m_valid, //! reg
    input  wire              m_ready, //! downstream ready
    output wire [DATA_W-1:0] m_data   //! reg
);
    reg  [DATA_W-1:0] s1_data_ff;
    reg               s1_valid_ff;
    wire              accept = s_valid & s_ready;

    always @(posedge clk) begin                  // control: reset
        if (!rst_n)       s1_valid_ff <= 1'b0;
        else if (s_ready) s1_valid_ff <= s_valid;
    end

    always @(posedge clk)                        // datapath qualified by valid: not reset
        if (accept) s1_data_ff <= s_data;

    assign s_ready = ~s1_valid_ff | m_ready;
    assign m_valid = s1_valid_ff;
    assign m_data  = s1_data_ff;
endmodule

`default_nettype wire
```

Naming: `_ff` register, `_ns` next-state/next-value, `s<N>_` pipeline stage,
`s_`/`m_` slave/master port groups, `u_` instance, `UPPER_SNAKE` parameters,
`*_W` widths, `*_NO` counts. Clock `clk` and reset `rst_n` are the first ports.

## 4. Coding rules that prevent bugs

- **Combinational blocks** assign a default to every output at the top; every
  `case`/`casez` has `default :`. `?` only in `casez` patterns.
- **One driver per signal.** Each `reg` is written by exactly one `always`.
- **FSM**: state in `state_ff`, next state in one `always @*` computing
  `state_ns` with `default :` back to a safe state; named `localparam`
  encodings; outputs in their own logic.
- **Reset scope**: reset every control/state register and anything that gates a
  handshake; wide datapath registers qualified by a valid may stay un-reset
  (comment it). Never reset a memory array.
- **Handshake (valid/ready)**: transfer on `valid && ready` at the edge; `valid`
  must not depend combinationally on `ready`; once high, `valid` and data hold
  until accepted. `ready` may be registered (skid buffer) or comb — record which.
- **`valid` travels with its data** through every pipeline stage.
- **Finalize from registers**: a DONE state reads `_ff` values, never the
  next-round combinational wires (that applies one extra round).
- **Initialize everything the result depends on** at operation start (IV,
  chaining value, accumulator), not only the working registers.
- **Co-asserted events** (push and pop, set and clear) are separate `if`s or an
  explicit both-high case — never `if/else if`, which drops one.
- **One-shot events win over clears**: a sticky/W1C bit gives set priority over
  clear in the same cycle, or the event is lost forever.
- **Same-cycle consumption**: data a submodule needs on the edge it arrives must
  use the input path, not a parent register written on that same edge.
- **Widths**: size literals (`8'd0`) where width is not obvious; truncate
  explicitly after a carry-out; check every concatenation member's width.
- **CDC**: only through a documented synchronizer. Single bits use 2 flops
  `x_meta_ff → x_sync_ff`, both `(* ASYNC_REG = "TRUE" *)` (keeps them together and
  out of optimization, and lets `report_cdc` recognize them). Counters and pointers
  use gray code; data buses use req/ack or an async FIFO; pulses use a toggle
  (`patterns.md` P17). Never sample a foreign-domain signal directly; the source
  of a crossing is a flop in its own domain, with no logic between it and the
  first synchronizer flop or between the synchronizer flops. The matching XDC is
  in `vivado-flow/board-reference.md` §3.
- **Named constants**: fixed encodings (opcodes, response codes, FSM states)
  are `localparam`s used by name; derive widths from parameters, never repeat
  a literal. Write each parameter's legal range in its `//!` comment.
- **Unsupported input**: every illegal or unsupported request has the response
  the spec defines (error, ignore, recover). If the spec does not say, record an
  `assumption` — do not let the code pick one silently.

## 5. Vivado-friendly RTL

- Synchronous reset (Xilinx UG949 recommendation; async resets block DSP/BRAM
  register absorption). Reset polarity comes from the spec.
- RAM: one clocked write `if (we) mem[a] <= d;`, registered read for block RAM,
  `(* ram_style = "block"|"distributed"|"registers" *)` when the size calls for it.
- Use clock enables, never gated clocks.
- Keep logic between registers within the project's logic-level budget
  (`project.json` → `impl.logic_level_budget`, default 12). A multiplier followed
  by an adder tree, or a long compare chain feeding a mux, needs a pipeline
  stage — and the latency in your report changes with it.
- No `initial` blocks, no `$display` without `` `ifdef SIM ``.

## 6. Self-check before you write the file

1. Reset: every control/state `_ff` has a reset value.
2. `<=`/`=` discipline; one driver per `reg`; no latches.
3. Each output's `reg`/`comb` timing matches your plan.
4. Count register stages input→output: equals your stated latency; `valid`
   aligned with data.
5. Walk the spec's first example (or REQ-1/REQ-2 scenario) through the code for
   3 cycles by hand.
6. Scan `patterns.md` bug table rows 1–22 against your code.
7. Run `style` and `lint`; cite their evidence IDs as `tool_result` claims.

## 7. Fix tasks (`fix-N`)

Read the failure evidence (`python3 tools/mae.py evidence <EV-ID> --log`) and
the triage hypothesis (a hypothesis, not a fact). Change the minimum that makes
the cited requirement hold. Do not change ports, widths or latency (that is an
interface decision for a human). Do not resubmit a version already tried — it is
rejected and counts against the budget. State in a `hypothesis` claim what was
wrong and why the change fixes it.
